# 辽轨 Demo 功能参数补齐 PRD

## 背景与目标

当前 Demo 已具备三角色界面、Mock 成绩、能力图谱、百炼报告和环境图片分析，但标书中的演示链路仍不完整。本轮在不接校方 MySQL、不导入真实校方数据的前提下，用可追溯的 SQLite/Mock 数据补齐功能性参数，使评标演示能够从规则配置一路核对到成绩、能力、报告和人工复核结果。

## 用户与核心任务

- 学生：查看本人历史成绩、单次步骤明细、能力图谱、毕业达标和诊断报告。
- 教师：限定在授权班级内查看班级概览、学生综合详情、单次成绩证据、报告和环境复核任务。
- 管理员：维护演示项目评分规则、步骤能力映射、毕业阈值、标准状态图片，并触发可追溯重算。
- 评标人员：按 ● 参数完成可重复、可核验的现场演示。

## 本轮范围

1. 评分规则、步骤能力映射与重算闭环。
2. 单次成绩明细及来源/规则/汇总证据。
3. 能力雷达图、子能力与支撑证据下钻。
4. 教师班级概览、统计时间范围及学生综合详情。
5. 异步诊断报告任务，显式展示提交、处理中、完成或失败。
6. 环境 AI 原始结果与教师确认、修改、驳回、备注审计。
7. 三角色接口数据范围修复与越权验收。
8. Mock 同步批次演示及 50 并发性能证据。

## 非目标

- 校方 MySQL 连接、数据字典适配和真实自动增量同步。
- 真实学生或真实实验室图片。
- 将演示压测结果表述为采购人最终服务器上的正式验收结论。

## 成功标准

- 标书中除 MySQL/真实数据依赖外的 ▲、● 功能均有可操作页面、持久化结果和接口测试。
- 任意能力结果可追溯到项目、步骤、状态、得分和当前映射。
- 教师无法通过任何成绩、能力、报告、环境接口访问非授权班级数据。
- 管理员修改规则或映射并重算后，成绩与能力结果同步变化且记录重算批次。
- 报告与环境任务有明确状态及失败原因，不用同步阻塞冒充异步任务。

## 约束与风险

- 所有页面继续显示 Mock/演示数据标识。
- LLM/VLM 失败时保存失败状态与可理解原因，不生成伪造内容。
- 环境复核保留 AI 原始结果，人工修改不得覆盖原始证据。
